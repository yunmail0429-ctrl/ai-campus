# 结构化知识入库与混合检索设计

日期：2026-09-23

## 目标与约束

在一台 8 核 CPU、8 GB 内存、100 GB 存储的服务器上，让电子文档、扫描件、图片、复杂表格与图表进入可追溯的知识库。用户检索时合并语义与关键词结果，使用重排模型选择证据，再由现有回答模型生成带来源的答案。

解析结果保留原文的页、块、表格和阅读顺序；可检索文本按这些信息重组，但不承诺与原文件像素级一致。原件继续保存在私有对象存储中。服务器不常驻视觉大模型或重排模型。

## 已确认方案与备选

采用本机文本解析和 CPU OCR、按需调用外部视觉模型、Qdrant 稠密向量与 BM25 关键词召回、外部重排接口。这样把常规入库留在本机，昂贵的视觉调用限于必要页面。

备选一是所有页面都交给视觉模型；实现路径较统一，但调用量、费用和等待时间随页数直接增长。备选二是本机部署全部模型；在现有内存及与 PostgreSQL、Redis、MinIO、ClamAV、应用进程共存的条件下，无法为视觉模型和重排模型保证稳定容量。

## 当前系统与改动边界

当前上传链路为私有原件、Outbox、Celery、ClamAV、独立解析进程、段落、嵌入向量、PostgreSQL pgvector 检索。图片直接返回 `OCR_REQUIRED`；扫描 PDF 遇无文字的图像页也返回该状态。电子 PDF 用 pypdf，docx 用 python-docx，pptx 用 python-pptx。分段按字符位置切割，未保留块级结构；检索先按权限过滤，再做余弦相似度排序，最多取六段。

本次保持现有上传 API、对象存储、Outbox、任务恢复、回答引用和计费边界。新增解析编排、结构化内容、Qdrant 索引与混合检索、重排配置。原文件和结构化内容以 PostgreSQL 与对象存储为权威来源，Qdrant 是可重建的检索副本。

## 解析与结构化表示

每份文档建立不可变的解析版本。版本记录解析器版本、OCR 引擎版本、视觉模型标识、开始/完成时间与错误码。每页或幻灯片保存有序内容块：`kind`（标题、段落、列表、表格、图片说明、图表说明）、`page`、`order`、`bbox`（可用时）、`text`、`markdown`、`source`（原生提取、OCR、视觉模型）、`confidence`、`asset_key`（可选）。表格另存二维单元格与合并关系；跨页表格以关联标识连接。页面阅读顺序由块顺序给出，无法可靠推断时标记待核对，不伪造布局关系。

对电子 PDF、docx、pptx、HTML 和纯文本，先用现有解析器提取。PDF 页面无可用文本、图片上传和文档中需要读取文字的图片区域转入 CPU OCR。OCR 使用本机 Tesseract 中文简体及英文语言包；OCR 子进程设超时、页数与像素上限，入库并发默认为 1。图片、表格和图表即使包含文字，也需要描述其关系或数据含义；复杂表格、图表、低置信度 OCR 区域交给可配置的外部视觉接口。视觉请求仅发送经过病毒扫描的单页或裁剪区域，限制尺寸、Token、超时、重试次数和单文档调用页数。接口未配置或调用失败时，保留已提取内容，标记该区域 `needs_review`；只有完全没有可检索内容时文档才保持解析失败。

视觉接口必须输出受限 JSON：块类型、文本、表格单元格、图表可观察的标题、坐标轴、图例和数据关系。服务端验证页码、顺序、长度和字段，不把推测的数值当作事实。每个块可同时保存原始 OCR 文本与视觉解释，检索正文使用经校验的拼接文本。表格用 Markdown 加单元格结构生成可检索内容；图片与图表使用可追溯说明。按页、块顺序重组 Markdown 供预览和分段，引用仍指向原文页与块。

分段以完整标题、段落和表格为边界，长块再切分，保留 `block_ids`、页码范围和原文偏移。分段文本不超过当前嵌入模型输入上限；表格的表头随切分片段重复，以免丢失列语义。旧版只含 `location/content` 的段落仍可读取，重新解析后生成新版结构。

## 模型与资源配置

沿用学校现有的嵌入服务配置；入库与问题使用同一有效嵌入模型及维度。新增视觉服务和重排服务配置，均由管理员维护、凭据仍通过服务端 Secret 引用。视觉接口采用受控的图像输入/JSON 输出适配器；重排接口接收一个问题和候选段落，返回候选 ID 与分数。两者都设置连接检查、输入上限、超时和审计调用量。生产环境使用 HTTPS；文档内容只发往管理员明确配置的服务。

在 8 GB 服务器上，Qdrant、PostgreSQL、Redis、MinIO、ClamAV、API 和 Worker 共用内存。OCR 同时只处理一个文档；视觉、嵌入和重排各设有限并发。Qdrant 向量、索引和 payload 优先使用磁盘/内存映射，payload 仅包含检索和过滤所需字段；容量门槛以实测向量数量、维度、磁盘占用和峰值 RSS 确定。对象存储设置容量告警并保留备份空间，不用“100 GB”推断可上传的文档总量。

## Qdrant 索引与迁移

一个检索点对应一个分段，稳定 ID 由租户、文档、解析版本、分段位置确定。稠密向量来自现有嵌入模型；关键词向量使用 Qdrant BM25，多语言分词配置在入库和查询时保持一致。payload 保存租户、库、文档、所有者、范围、对话 ID、索引版本、页码范围和段落 ID，不复制完整私有原文。为租户、索引版本、库和可见范围建立过滤索引。部署时固定并验证支持所需 BM25 与混合查询能力的 Qdrant 版本。

PostgreSQL 中记录索引任务、目标版本、已写入点数和切换状态。解析块与分段先提交数据库；Outbox 驱动幂等 Qdrant upsert。全部点写入并抽样读回后，文档才切换到新版 `ready`。旧版在切换前继续服务；切换后异步删除旧点。嵌入模型或维度变化时建立新的索引版本并回填，不在写入过程中把不同模型的向量混入同一可检索版本。迁移现有 pgvector 数据时先回填 Qdrant、比对文档和段落数量及权限测试，再切换检索读取；失败则继续使用原检索路径。删除文档先在 PostgreSQL 中撤销可见性，再通过 Outbox 清理 Qdrant，避免延迟删除时泄露内容。

## 检索、重排与回答

问题先经现有脱敏处理，并由有效嵌入模型生成查询向量。Qdrant 在同一权限过滤条件下分别召回稠密向量与 BM25 候选，使用 RRF 合并，取有限候选集（默认每路 20 个、合并后最多 30 个）。中文关键词召回与英文词、编号、日期共同验收。召回结果必须回 PostgreSQL 按租户、用户、学校库/个人库/当前对话附件、文档状态和索引版本重新核对；只从数据库读取原文，不信任 Qdrant payload 的授权信息。

重排接口仅接收已核权的候选文本，返回排序分数；最多六段进入现有 `context_for` 预算控制。重排失败或超时时按 RRF 结果继续，记录降级状态。若没有有效嵌入配置，知识库检索仍按现有错误语义返回。若视觉解析有未核对区域，引用带来源与“待核对”标记，回答提示资料内容可能不完整。生成模型只接收检索到的参考片段，不在原始文件上自行搜索；引用保存文档、解析版本、页、块和摘录，历史引用再次核权。

## 失败、安全与恢复

所有文件在解析和任何模型调用前完成病毒扫描。解析进程继续隔离并限制内存、CPU、时间、压缩包膨胀、页数和输出大小；视觉模型输出按不可信数据验证，绝不执行文档中的指令。服务端日志和错误码不写入私有正文、外部接口密钥或模型原始异常。外部调用超时可重试，幂等键防止重复写块或重复索引；不可恢复的区域失败记录在解析版本中供人工重试。模型调用量与不确定计费单独记录，教师积分仍只对回答生成扣费。

## 验收

1. 电子 PDF、Word、PPT、HTML、文本、扫描 PDF 和图片均有可追溯的页/块顺序；扫描件与含文字图片能由 OCR 入库。
2. 复杂表格保留表头、单元格与阅读顺序；图表说明仅包含从图像可核对的信息。无法确认的数值标为待核对。
3. 同一批测试文档包含中文近义提问、精确校名/编号、表格字段和图表问题；分别验证向量、BM25、融合与重排的召回和最终引用。
4. 跨校、跨教师、跨对话与删除后的 Qdrant 结果均不能越权返回；数据库复核是最后一道授权判断。
5. OCR、视觉接口、Qdrant、重排接口分别断开时，任务状态、重试与降级符合上述语义，不产生虚假引用。
6. 在目标服务器或等价资源限制下测入库并发、峰值内存、磁盘增长、检索延迟和恢复时间，再据结果调整队列与容量阈值。

## 实施顺序

先交付结构化解析与 CPU OCR，使原文块可追溯；再接视觉兜底及其审核状态；随后搭建 Qdrant 与迁移回填，切换混合召回；最后接重排与端到端验收。各阶段保留可运行的既有问答链路。
