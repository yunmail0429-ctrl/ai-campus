## 方案比较

| 项目 | ai校园 Node 后端 | 当前项目现状 / 建议 |
|---|---|---|
| PPT | 文本模型生成 Markdown，再由本地函数创建 PPTX | 尚无生成适配器。建议采用同一路径，但在 Python 中实现真实可编辑 PPTX，明确页数、内容结构和溢出验证 |
| 图片 | 单独调用图片 API，校验 PNG 文件头后存储 | 尚未接入；保留独立适配器和私有产物处理 |
| 视频/音乐/数字人/3D | 可配置媒体连接器，约定返回 base64/mime/name；仍待特定供应商验收 | 用户暂无指定服务，不将连接器协议视为已接入能力；保留明确未配置状态 |
| 积分 | `core.mjs:317` 的 creditQuote 按类型固定报价；PPT 默认 3、图片 4、媒体 6，可配置；Workflow 可加价 | 已确认创作扣教师积分，尚未确认固定报价还是实际用量。建议媒体固定报价由管理员配置，普通文字回答保留现有 Token 计费；不擅自复制参考默认数值 |
| 冻结/结算 | Worker 开始时减少可用分，完成存储后记录成功，失败退款 | 保留本项目独立余额/预占账本、提交时预占及幂等；按任务快照结算，失败/取消释放 |
| 排队 | 数据库写入后直接 BullMQ 入队；入队失败回写失败状态 | 保留现有 PostgreSQL + 事务 Outbox + Celery，不更换技术栈 |
| 取消/重启 | Redis 取消标记与 AbortController；发现 RUNNING 重投时按中断失败处理 | 后续 Worker 实现需覆盖外部任务 ID、租约、取消与完成竞争及未知费用窗口，不直接复制简化流程 |

## 教学草稿版本

参考 `core.mjs:169` 的 update 接收可选 revision，更新成功后 revision 加一；有传 revision 时旧版本更新返回 409。该片段未提供完整教学草稿快照历史。本项目保存接口要求 revision，历史内容独立存表，恢复也形成新版本；旧稿迁移保留为 v1。前端冲突保留本地输入，并提供明确保存为新版本的操作，见 DRAFT-VERSIONS.md。

参考 Node 后端 `worker.mjs:410` 附近先执行病毒扫描，再向 `PARSER_URL/parse` 提交文件名和 base64，接收 chunks 后调用向量服务。桌面文件集合中未找到对应解析服务代码，因此不能确认其 OCR 引擎、识别质量或是否收费，也不能把 README 中的测试描述当作本次验证结果。
