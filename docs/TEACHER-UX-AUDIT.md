# 教师视角产品流程审查（2026-09-23）

本审查以教师完成备课、资料检索、创作和复用教学方法为主线；学校管理员以查看使用情况、分配积分和审核共享方法为主线。依据当前 `frontend/src/components`、后端接口和浏览器回归结果。设计取舍参考 [NN/g 对看板的研究](https://www.nngroup.com/articles/dashboards-preattentive/)：总览应帮助用户快速看懂变化，详细记录留给需要追查时使用。

| 流程 | 用户要完成的事 | 发现的问题 | 当前处理 |
| --- | --- | --- | --- |
| AI 工作台 | 输入教学需求、附加资料、选方法并开始 | “添加资料”缺少悬停和文件状态；最近工作只有小链接可点 | 添加按钮悬停/选中与文件名反馈；最近工作和常用方法整行可点 |
| AI 助手 | 继续对话、引用资料、查看草稿 | 附件按钮缺少文件状态；部分次级按钮缺少统一反馈 | 附件状态和全局次级按钮反馈已补 |
| 教学助手（Skill） | 把教学经验变成可复用助手 | 直接要求写教学指令和测试样例，教师需要懂配置概念 | 新建改为学科、年级、主题、学习目标、产出和课堂要求；自动生成可预览模板；分享前提供五个可修改的课堂问题示例 |
| 教学资料 | 上传、处理、检索资料 | 上传后处理状态较技术化，扫描件依赖 OCR 服务 | 保留明确的上传与检索状态；后续应把 OCR 未配置提示放在选择文件前 |
| AI 创作 | 选择形式、描述作品、查看进度 | 类型已选中的状态曾不够明显；过去仅视频会提前查询服务状态 | 强化类型选中态；所有创作类型在填写前显示服务可用性和不可用原因，视频显示已有的积分预估 |
| 个人设置/积分 | 设置默认选项、理解用量 | 积分只显示余额，不说明变化来源 | 保留余额和个人明细；侧栏积分按钮只作轻按压反馈，不伪装成跳转 |
| 学校管理首页 | 一眼看到近期使用与产出 | 原入口落在账号列表，统计只有指标和明细表 | 默认进入学校看板，增加每日趋势与重点指标 |
| 积分管理 | 找到哪个教师为什么发生积分变化 | 必须逐个打开账户看流水；原记录不便横向比较 | 新增跨教师近期积分变化表，显示时间、教师、类型、变动、事项；账号操作保持在下方 |
| Skill 审核 | 理解方法是否适合全校分享 | 风险边界、样例等术语偏技术 | 教师填写端改为课堂语言；后续应将审核端也改成“适用场景/课堂试用”的对照视图 |
| 审计记录与模型配置 | 排错或管理服务 | 面向技术排错，不是教师日常入口 | 保留在管理员次级导航；后续应把常见异常转成可操作提示，原始追踪号保持折叠 |

交互约定：能操作的按钮与整行入口应有悬停、按压和键盘焦点反馈；已选中状态只用于真实持续选择；上传文件后显示文件名和移除入口；不可用操作同时给出原因，避免只有灰色按钮。

后续验收重点：在真实 `localhost:3100` 页面逐页检查老师与管理员两种账号；核对积分表只显示当前学校数据；确认 Skill 模板在保存、重新打开、分享试用之间可读且不丢失。
