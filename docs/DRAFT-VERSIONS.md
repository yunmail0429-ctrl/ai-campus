# 教学草稿历史版本

参考 ai校园 `core.mjs` 的 revision 条件更新，结合 PRD 中教师保存版本的要求，本项目为教学草稿增加独立历史快照和版本恢复。保留现有 React 编辑面板，历史列表默认折叠。

## 接口

- `GET /api/v1/conversations/{id}/draft` 返回 content 和 revision（空白新对话为 0）。
- `PUT /api/v1/conversations/{id}/draft` 必须提交 content 和读取时的 revision。此版本将 revision 设为必填，外部调用方需要先 GET；导出接口仍只接收 content/format。
- `GET /api/v1/conversations/{id}/draft/versions` 返回版本摘要，不含正文；limit 默认 20、最大 100，cursor 为上页返回的版本号边界字符串，按版本号倒序分页。
- `GET /api/v1/conversations/{id}/draft/versions/{number}` 返回本人历史内容。
- `POST /api/v1/conversations/{id}/draft/versions/{number}/restore` 提交当前 revision，将历史内容保存为新版本，并记录 restoredFrom。

以上接口只允许同校对话所有者访问，管理员也不能查看其他教师私人草稿；软删除对话后历史接口同样拒绝访问。现阶段没有单条历史删除或保留期限清理功能，软删除不物理删除历史内容。

## 保存语义

通过会话行锁串行处理同一草稿更新，数据库以 tenant/conversation/number 唯一约束保证版本号不重复。修改保存和恢复在同一事务更新当前草稿、追加快照和审计。正文相同的重复保存/恢复返回当前版本，不重复添加快照；有差异但 revision 过旧返回 `409 DRAFT_VERSION_CONFLICT`，不覆盖当前稿。

前端有未保存修改时，后台重新查询不会覆盖编辑框；冲突后可查看最新历史，再明确点击“将我的修改保存为新版本”。保存/恢复期间禁用编辑，未保存修改时禁用历史恢复。版本操作不调用模型、不消耗积分；审计仅包含版本号和恢复来源，不包含正文。

已完成回答提供“加入教学草稿”：把回答正文追加到当前草稿末尾并打开编辑面板，保留教师已有备注，标记为未保存，教师点击保存后才形成新版本。读取草稿中、保存/恢复中或合并后超过 200000 字符时禁用追加。运行中和中断的回答不显示该操作。

## 迁移与验证

回答加入草稿时，附带参考资料编号、标题和位置，供保存版本和导出后核对。不复制私有下载地址、内部 ID 或引用摘录；不可用来源仅保留编号与失效提示。来源标签转义 Markdown，合并长度限制包含来源内容。生产构建和来源转换专项通过；该专项为纯函数校验，不计作浏览器端到端验收。

迁移 `8dde7b50e065` 创建 draft_versions，将旧数据库中每个非空草稿复制为 v1，保留原草稿和时间。迁移降级保留当前 Conversation.draft，但会删除历史表，因此不能把降级当作历史备份方式。

SQLite/PostgreSQL 专项验证同内容重试、旧版本冲突、双请求竞争、恢复来源、版本分页、权限/软删除、无积分变化、审计不含正文和既有草稿迁移。浏览器通过实际 Next/FastAPI 验证保存 v1/v2、未保存时禁止恢复、恢复新版本、另一页面更新后的本地文本保留与明确重试；三格式导出同时回归通过。手机历史列表已检查。

原有 live.spec.ts 四项实际前后端场景回归通过，其中模型协议夹具场景新增“生成回答 → 保留教师备注并追加 → 保存 v1 → Markdown 下载 → 核对累计仍只消耗生成时的 1 积分”。模型结果来自本地协议夹具，不视为真实供应商教学质量验收。
